# CLAUDE.md — Next.js Application

This is a Next.js project that integrates TypeScript and TailwindCSS, built as a static export and served from S3 behind CloudFront. Refer to `package.json` for the specific versions of the dependencies used; ensure the correct syntax and features for those versions when making changes.

## Project Structure

All the folder and file names are in kebab-case, except for `components/*`:

- `app/` — the routes that follow the Next.js App Router convention. Everything must be statically exportable (`output: "export"`); no Server Actions, API routes, or request-time rendering.
- `components/` — reusable components, named using PascalCase:
  - `Content*`: composite components; most others are named after their outer element, usually a HeroUI component, e.g. `Card*`, `Button*`.
  - `components/*.tsx` when a component is self-contained; `components/*/index.tsx` when it contains sub-components in the same folder.
- `files/` — markdown and data files served through helper functions:
  - `files/articles/`: blog posts named `YYYY-MM-DD.md` (see `CLAUDE.md` in that folder for the writing guide, and `getArticleByFilename` in `helpers/server/article.ts` for front-matter fields).
  - `files/documents/`: other markdown files, each with its own front-matter contract (see `getProfile` in `helpers/server/document.ts`). The sections between `<!-- generated:*:start/end -->` markers in `Profile.md` are generated by `scripts/build-profile.mjs` — edit `files/resume/Resume.yaml` instead.
  - `files/resume/`: the resume source of truth (constraints in the root `CLAUDE.md`).
- `helpers/` — functions shared across server and client environments. Helpers for the same domain share a filename, e.g. `helpers/article.ts` and `helpers/server/article.ts`; `helpers/server/*` is server-only, `helpers/client/*` is client-only.
- `public/` — static assets. Article-scoped images live in `public/images/<YYYY-MM-DD>/` named `Pascal-Case.ext`, e.g. `public/images/2024-08-19/Branch-Name-LTS.png`.
- `scripts/` — build scripts run through the npm scripts in `package.json` (`build-resume.mjs`, `build-profile.mjs`).
- `settings/` — configuration and constants: `config.ts` (home page data), `constant.ts` (global constants), `heads.ts` (metadata/viewport/fonts), `icons.ts` (icon mapping).
- `stores/` — global state management using Zustand; some states are parsed before everything loads in `components/Entry.tsx`, contained in the root layout `app/layout.tsx`.
- `styles/` — global CSS styles.

The `Dockerfile` only builds the resume documents (LibreOffice and pandoc live in the image); the website itself is built with `npm run build` on the host.

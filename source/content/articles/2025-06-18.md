While building this personal website and blog, I needed a way to display code snippets with syntax highlighting and special formatting capabilities. I started with a simple implementation using [Highlight.js](https://highlightjs.org/), but as I wrote more technical articles, the requirements grew more complex.

The component evolved through several iterations: basic syntax highlighting, then a copy-to-clipboard button, support for highlighting specific lines, error highlighting, and eventually a complete parsing system for custom markdown directives. As the feature set expanded, I realized I needed filename support for code blocks, which led me down the path of the Rehype ecosystem.

Eventually, I discovered [Rehype Pretty](https://rehype-pretty.pages.dev/), a comprehensive solution that handled everything I had built and more, making my custom component obsolete. However, the journey was educational and the component might still be useful for developers who need a simpler solution without diving into AST parsing.

This article serves as a retrospective on building a custom code highlighting component from scratch, documenting the challenges and solutions I encountered along the way.

## Component Architecture

The core component consists of three main parts:

1. [Main React Component](#main-react-component): Handles rendering and highlighting
2. [Parser Function](#parser-function): Processes special syntax markers
3. [Styling System](#styling-system): Manages different highlight levels

### Main React Component

The React component handles syntax highlighting and renders different code sections with appropriate styling. Some properties and functions are removed or simplified for readability:

```tsx
"use client";

import { useRef, useEffect, useState } from "react";
import clsx from "clsx";
import highlight from "highlight.js";

import { getKeys, getValues } from "@/helpers/utility";

const LEVEL_TO_CLASSNAMES = {
  error: "bg-red-900/50",
  highlight: "bg-default-700 dark:bg-default-300/50",
} as const;

function parseRaw(content: string) {
  ...
}

export default function CodeBlock({ children, className }) {
  const refItems = useRef([]);

  const [isHighlighted, setIsHighlighted] = useState(false);

  useEffect(() => {
    if (refItems.current) {
      for (const item of refItems.current) {
        if (item === null) continue;
        highlight.highlightElement(item);
      }
      setIsHighlighted(() => true);
    }
  }, []);

  const sections = parseRaw(children);

  return (
    <div data-highlighted={isHighlighted}>
      <pre className="hljs">
        {sections.map((section, indexSection) => {
          const isLastSection = indexSection === sections.length - 1;
          return (
            <div
              ref={(element) => {
                if (refItems.current === null) refItems.current = [];
                refItems.current[indexSection] = element;
              }}
              key={indexSection}
              className={section.level
                ? LEVEL_TO_CLASSNAMES[section.level]
                : "bg-transparent"}
            >
              {section.lines.map((line, indexLine) => {
                const isLastLine = indexLine === section.lines.length - 1;
                return isLastSection && isLastLine ? line : line + "\n";
              })}
            </div>
          );
        })}
      </pre>
    </div>
  );
}
```

:::fact
The component uses `useEffect` to apply Highlight.js syntax highlighting after the DOM elements are rendered.
:::

### Parser Function

The `parseRaw` function is the core parsing logic that processes special syntax markers in code blocks. It handles directives like `highlight-next-line`, `error-start`, `error-end`, and similar patterns.

#### Function Signature and Setup

```typescript
function parseRaw(content: string) {
  const lines = content.split("\n");
  const result: {
    lines: string[];
    level?: keyof typeof LEVEL_TO_CLASSNAMES;
  }[] = [];
  let buffer: string[] = [];
```

#### State Management

The parser maintains state for tracking highlighting modes. This can be converted to a simple key-value object if no further extensions are needed:

```typescript
const state: {
  [key in "next"]: {
    [key in keyof typeof LEVEL_TO_CLASSNAMES]: boolean;
  };
} = {
  next: { error: false, highlight: false },
};
```

#### Line Processing Loop

The main parsing loop iterates through each line and checks for directive patterns. `isHandled` is used to indicate if the line contains a directive The handlers are introduced in the following sub sections in the execution order:

```typescript
for (const line of lines) {
  let isHandled = false;

  getKeys(LEVEL_TO_CLASSNAMES).forEach((level) => {
    ...
  });

  if (!isHandled) buffer.push(line);
}
```

##### Handling Start Markers

When encountering a `level-start` directive, add the current buffer to the result and start:

```typescript
if (line.includes(`${level}-start`)) {
  if (buffer.length > 0) {
    result.push({ lines: buffer });
    buffer = [];
  }
  isHandled = true;
  return;
}
```

##### Handling End Markers

When encountering a `level-end` directive, add the current buffer to the result and stop highlighting for that level:

```typescript
if (line.includes(`${level}-end`)) {
  if (buffer.length > 0) {
    result.push({ lines: buffer, level });
    buffer = [];
  }
  isHandled = true;
  return;
}
```

##### Handling Next-Line Markers

When encountering a `level-next-line` directive, flag the next line and add it as an array with the current level:

```typescript
if (line.includes(`${level}-next-line`)) {
  if (buffer.length > 0) {
    result.push({ lines: buffer });
    buffer = [];
  }
  state.next[level] = true;
  isHandled = true;
  return;
}

if (state.next[level]) {
  result.push({ lines: [line], level });
  state.next[level] = false;
  isHandled = true;
  return;
}
```

##### Handle Buffer Cleanup

```typescript
if (buffer.length > 0) {
  result.push({
    lines: buffer,
    level: getKeys(LEVEL_TO_CLASSNAMES).find((key) =>
      getValues(state).some((values) => values[key]),
    ),
  });
}

return result;
```

:::note
The parser removes directive lines from the output, so `highlight-start` and similar markers won't appear in the rendered code block.
:::

### Styling System

The component uses a simple mapping system to apply different background colors for highlight levels:

```typescript
const LEVEL_TO_CLASSNAMES = {
  error: "bg-red-900/50",
  highlight: "bg-default-700 dark:bg-default-300/50",
} as const;
```

Each parsed section receives the appropriate class based on its level, with regular code getting `bg-transparent` as the default.

## Usage Examples

The component supports several highlighting patterns. For example, you can use `start` and `end` markers to highlight multiple consecutive lines:

```cpp
// highlight-start
int main() {
  std::cout << "This function will be highlighted" << std::endl;
  return 0;
}
// highlight-end
```

You can use `next-line` markers to highlight only the following line:

```cpp
// highlight-next-line
void highlighted() {
  std::cout << "Only this function signature is highlighted" << std::endl;
}

// error-next-line
void problematicFunction() {
}
```

You can combine different highlighting types in the same code block:

```cpp
// highlight-next-line
const int validConfig = 5000;

void processData(const std::vector<std::string>& data) {
  // error-start
  if (data.empty()) {
    throw std::runtime_error("Data is required");
  }
  // error-end

  // highlight-start
  std::vector<std::string> result;
  for (const auto& item : data) {
      if (!item.empty()) {
          result.push_back(item);
      }
  }
  // highlight-end
}
```

## Migration to Rehype Pretty

Eventually, I migrated to [Rehype Pretty](https://rehype-pretty.pages.dev/), mainly because:

- **AST-Based Processing**: More robust parsing at the markdown/HTML level
- **Built-In Features**: Copy buttons, line numbers, and filename support

:::fact
If you need a quick solution for code highlighting without the complexity of AST processing, this custom component is still a viable option. However, for production applications with growing requirements, consider established solutions like [Rehype Pretty](https://rehype-pretty.pages.dev/) or [Prism.js](https://prismjs.com/).
:::

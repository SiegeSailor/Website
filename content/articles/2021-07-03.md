During development, sometimes you want to split out modules for specific purposes or for sharing, and maintain them as packages. Since these are for team use, you may not want to publish them directly on public NPM. In this case, registering a Private Package on your own domain that requires authentication is the best choice.

<!-- description -->

## Usage

One way to use Private Packages on GitLab is to specify the domain and authorization directly in the install command:

```shell
npm install --save git+https://<username>:<password>@<gitlab_domain>/<group_name>/<project_name>.git
```

The last 3 items, `gitlab_domain`, `group_name`, and `project_name`, can be found directly in the URL of the project you want to share as a Private Package. The URL should look like `https://gitlab.example.tw/group_name/project_name`.

:::fact
`username` and `password` here do not refer to your GitLab user account, but are provided by the Deploy Token.
:::

## Generating a Deploy Token

First, go to `Settings / Repository / Deploy Tokens` in GitLab:

![Deploy-Token-Menu](/images/2021-07-03/Deploy-Token-Menu.png)

Then generate the Deploy Token you need. Note that Name is only for identification in GitLab, Username is part of the token, and the Scopes must include at least `read_repository`:

![Deploy-Token-Section](/images/2021-07-03/Deploy-Token-Section.png)

After completion, you should see:

![Deploy-Token-Done](/images/2021-07-03/Deploy-Token-Done.png)

As shown above, the Deploy Token consists of a `username` and `password`. To use this for package installation, simply use the following command in another project:

```shell
npm install --save git+https://gitlab+deploy-token-custom:4XPcqWQC9yGUvcy6Lw2D@gitlab_domain/group_name/project_name.git#v1.0.0
```

> `v1.0.0` is one of the tags for the project. You can specify a branch or tag after the `#` to choose the version to install.

## Troubleshooting

If you use the above method and run `npm ci` or `npm install`, you may encounter _Cannot find module/module not found_ during the CI/CD build stage. This is because, due to permission issues, the package was not successfully installed during `npm ci` or `npm install`, causing the project to miss modules during the build/compile stage.

To solve this, you can use the following commands in your CI/CD scripts:

```shell
npm config set unsafe-perm true
npm ci --allow-root
```

## Token Security Issues

One characteristic of using a token directly for Private Package access is that the path recorded in `package.json` is not just the package name, but includes the Deploy Token. This means if your project imports `package.json`, the Deploy Token will be built into and displayed in public compiled files.

GitLab provides two other methods:

- [Publishing Private Packages via GitLab Package Registry](/blog/2021-07-04)
- [Submodules](https://git-scm.com/book/en/v2/Git-Tools-Submodules)

Alternatively, you can use a self-hosted NPM registry like [Verdaccio](https://www.verdaccio.org/), which is independent of the GitLab workflow.

## Technical Screening Problems

During the second round, I was given two coding challenges that tested different algorithmic concepts.

### Above-Average Subarrays

You are given an array A containing N integers. Your task is to find all subarrays whose average sum is greater than the average sum of the remaining array elements. You must return the start and end index of each subarray in sorted order.

A subarray that starts at position L1 and ends at position R1 comes before a subarray that starts at L2 and ends at R2 if `L1 < L2`, or if `L1 = L2` and `R1 ≤ R2`.

:::note
We define the average sum of an empty array to be 0, and the indices of the array (for output) are 1 through N. A subarray containing a single element will have `L1 = R1`.
:::

**Constraints:** 1 ≤ N ≤ 2,000, 1 ≤ A[i] ≤ 1,000,000

```python
Input: A = [3, 4, 2]
Output: [[1, 2], [1, 3], [2, 2]]
```

The above-average subarrays are `[3, 4]`, `[3, 4, 2]`, and `[4]`.

#### Solution

I started with a brute force approach during the interview, then later optimized it using prefix sums:

```python title="Brute Force"
def bruteForce(A):
    result = []

    for i in range(0, len(A)):
        for j in range(i, len(A)):
            subarray = A[i : j + 1]
            m = sum(A[i : j + 1]) / len(subarray)
            if len(subarray) == len(A):
                result.append([i + 1, j + 1])
                continue

            am = sum(A[0:i] + A[j + 1 : len(A)]) / (len(A) - len(subarray))
            if m > am:
                result.append([i + 1, j + 1])
    return result
```

```python title="Optimized with Prefix Sums"
def aboveAverageSubarrays(A):
    result = []

    # Precompute prefix sums
    prefix = [0] * (len(A) + 1)
    for i, v in enumerate(A):
        prefix[i + 1] = prefix[i] + v

    for i in range(0, len(A)):
        for j in range(i, len(A)):
            subarray_len = j - i + 1
            remaining_len = len(A) - subarray_len
            if remaining_len == 0:
                result.append([i + 1, j + 1])
                continue

            # Calculate subarray sum in O(1) time
            subarray_sum = prefix[j + 1] - prefix[i]
            m = subarray_sum / subarray_len
            am = (prefix[-1] - subarray_sum) / remaining_len
            if m > am:
                result.append([i + 1, j + 1])
    return result
```

The optimization reduces sum calculation complexity from O(n) to O(1) per subarray.

### Answer a Query

Imagine a length-N array of booleans, initially all false. Over time, some values are set to true, and at various points in time you would like to find the location of the nearest true to the right of given indices.

You will receive Q queries, each of which has a type and a value. SET queries have type = 1 and GET queries have type = 2.

- SET query: The value denotes an index in the array that is set to true (1-indexed)
- GET query: Return the smallest index that contains a true value greater than or equal to the given index, or -1 if no such index exists

**Constraints:** 1 ≤ N ≤ 1,000,000,000, 1 ≤ Q ≤ 500,000

```python
N = 5, Q = 5
queries = [[2, 3], [1, 2], [2, 1], [2, 3], [2, 2]]
output = [-1, 2, -1, 2]
```

#### Step-by-step Execution

1. Initial state: `[false, false, false, false, false]`
2. GET 3 → -1 (no true values)
3. SET 2 → `[false, true, false, false, false]`
4. GET 1 → 2 (nearest true to the right of index 1)
5. GET 3 → -1 (no true values to the right of index 3)
6. GET 2 → 2 (value at index 2 is true)

#### My Solution

```python
Q_SET = 1
Q_GET = 2

def answerQueries(queries, N):
    states = [False] * N
    result = []

    for query in queries:
        t, i = query
        i -= 1  # Convert to 0-indexed

        if t == Q_SET:
            states[i] = True
        elif t == Q_GET:
            # Linear search from given index
            j = i
            while j < N:
                if states[j]:
                    result.append(j + 1)  # Convert back to 1-indexed
                    break
                j += 1
            else:
                result.append(-1)

    return result
```

This solution maintains a boolean array and performs linear search for GET queries. Given the constraints, a more sophisticated data structure like a segment tree might be needed for optimal performance, but this approach worked for the interview context.

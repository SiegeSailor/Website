This is for this website. I deployed my previous version using AWS Amplify, which was super easy to use, but I wanted more control over the infrastructure and reduce cost as well. So I decided to migrate to ECS Fargate using Terraform.

<!-- description -->

### Terraform Structure

I am still trying to find the best file structure for my monorepo. It may end up like below:

```plaintext
└── 📁 [module]
    └── 📁 docker-context
    └── 📁 infrastructure
        └── 📁 [environment]
    └── 📁 scripts
└── 📁 shared-infrastructure
    └── 📁 [environment]
└── 📁 scripts
├── .gitignore
├── CONTRIBUTING.md
└── README.md
```

The problem is that resources like VPC, subnets, and security groups should be shared across multiple services as I may only need one public resource, which is this Next.js application managed by ECS Fargate.

### Challenges

My container health status were constantly showing `Unknown` or `Unhealthy`, up to the tool I used for the health check command. Then I found out that defining environment variables in `Dockerfile` wasn't sufficient. I had to define the variables in the ECS task definition to ensure they were accessible at runtime:

```terraform
container_definitions = {
    (local.module) = {
        environment = [
            {
                name  = "HOSTNAME"
                value = "0.0.0.0"
            },
            {
                name  = "NODE_ENV"
                value = "production"
            },
            {
                name  = "PORT"
                value = tostring(local.port)
            }
        ]
    }
}
```

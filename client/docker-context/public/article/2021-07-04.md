As of today, there are many platforms for managing private NPM packages. But what if you want to quickly integrate this into your existing workflow? GitLab provides a Package Registry that integrates with the GitLab workflow, allowing you to publish, install, and manage private packages with authentication, all as part of your deployment process.

<!-- description -->

## Usage

GitLab's UI may change depending on the version, but the basic process should be similar to [GitLab Docs NPM Packages in the Package Registry](https://docs.gitlab.com/user/packages/npm_registry/). Here, we'll use a real example with a Group Scoped Deploy Token for authentication. First, select the project you want to use as a Private Package. It must be a project under a group. If you go to the project page in GitLab, the URL should be `https://gitlab.example.tw/group_name/project_name`. Next, set up `package.json`:

> For a video demo, see [GitLab Unfiltered](https://www.youtube.com/channel/UCMtZ0sc1HHNtGGWZFDRTh5A)'s [GitLab NPM Registry Demo](https://www.youtube.com/watch?v=yvLxtkvsFDA). The only differences are in the UI and how to use NPM config.

```json title="package.json"
{
  "name": "@group/project",
  "private": false,
  "repository": {
    "type": "git",
    "url": "https://gitlab.example.tw/group/project"
  },
  "version": "1.0.0",
  "publishConfig": {
    "@group:registry": "https://gitlab.example.tw/api/v4/projects/1/packages/npm/"
  }
}
```

The above omits unrelated fields.

`name` must be in the format `@group_name/anything`. GitLab enforces this strictly; if it doesn't match, `npm publish` will return a 400 error. See [GitLab Docs Package Naming Convention](https://docs.gitlab.com/user/packages/npm_registry/#package-naming-convention).

`private` must be set to `false` to share the package.

`repository` field is optional, but for reference, the key prefix in `publishConfig` should match the `url`'s `/group/` part, and the value's domain should be the same. If not, you'll get a 404 error.

`version` must be updated for each publish. If you try to publish the same package name and version again, you'll get a 403 error from `npm publish`. Note that the error message may differ from the 400 mentioned in the GitLab docs. See below:

```shell
npm ERR! code E403
npm ERR! 403 403 Forbidden - PUT https://gitlab.example.tw/api/v4/projects/1/packages/npm/@group%2fproject
npm ERR! 403 In most cases, you or one of your dependencies are requesting
npm ERR! 403 a package version that is forbidden by your security policy, or
npm ERR! 403 on a server you do not have access to.
```

`publishConfig`, besides matching the key prefix and value domain, note that `projects/1/packages`'s `1` is the Project ID assigned when the project was created. You can find it on the project's `Settings > General Settings` page:

![General-Settings](/image/2021-07-04/General-Settings.png)

Then, click the group in the image above to go to the Group Scoped page and create a Group Scoped Deploy Token:

![Deploy-Token](/image/2021-07-04/Deploy-Token.png)

:::fact
For how to create a Deploy Token, see [Using GitLab Deploy Token for Private Package Access](/blog/2021-07-03). You can also use Project Scoped Token, Personal Access Token, or `CI_JOB_TOKEN` for permissions.
:::

In the root folder, add a `.npmrc` file with the following content:

```shell
@game:registry=https://gitlab.example.tw/api/v4/packages/npm/
//gitlab.example.tw/api/v4/packages/npm/:_authToken=fgG4r21tRagJ3wBsuqa5
//gitlab.example.tw/api/v4/projects/147/packages/npm/:_authToken=fgG4r21tRagJ3wBsuqa5
```

:::note
If you don't want to deal with extra setup, you can use `npm config set` to save it locally. If you get a 401 error in the next step, check if any domain is incorrect. Since this file contains a token, it's recommended to remove `.npmrc` from version control.
:::

Finally, run `npm publish` to publish. Make sure to build or compile before publishing.

## Troubleshooting

This is different from the _403 Forbidden_ above. When following the GitLab docs, I kept getting a 403 error from `npm publish`. At first, I thought it was because a dependency couldn't be fetched, but after checking, all were from public NPM. Then I suspected a local [NPM Config](https://docs.npmjs.com/cli/v7/commands/npm-config) issue, so I used `npm config edit` to clear them one by one, but even with only `.npmrc` settings, I still got 403.

Finally, I found that in the project being published as a Private Package, you need to enable **Packages**. This feature is not enabled by default. The GitLab version I used was [v13.4.1-ee](https://gitlab.com/gitlab-org/gitlab/-/tags/v13.4.1-ee):

![General-Settings-Permissions](/image/2021-07-04/General-Settings-Permissions.png)

## Using with GitLab CI/CD

Since packages are usually published after a version update, you can integrate the above permissions, build, and publish steps into CI/CD, and set the trigger to `only: ['tags']`:

```yml title=".gitlab-ci.yml"
image: node:13.10.1

stages:
  - deploy

deploy:
  stage: deploy
  only: ["tags"]
  script:
    - echo CI_PROJECT_ID $CI_PROJECT_ID
    - echo CI_JOB_TOKEN $CI_JOB_TOKEN
    - echo "@game:registry=https://gitlab.example.tw/api/v4/packages/npm/" >> .npmrc
    - echo "//gitlab.example.tw/api/v4/packages/npm/:_authToken=${CI_JOB_TOKEN}" >> .npmrc
    - echo "//gitlab.example.tw/api/v4/projects/${CI_PROJECT_ID}/packages/npm/:_authToken=${CI_JOB_TOKEN}" >> .npmrc
    - cat .npmrc
    - npm ci
    - npm run build
    - ls -al
    - npm publish
```

:::note
`CI_PROJECT_ID` and `CI_JOB_TOKEN` are predefined variables that provide the project ID and permissions needed to run the job (equivalent to Deploy Token or Personal Access Token). For more, see [GitLab Docs Predefined Variables Reference](https://docs.gitlab.com/ci/variables/predefined_variables/).
:::

## Using Private Packages

In the root folder of the project where you want to use the package, add a `.npmrc` file with the following content:

```shell
@game:registry=https://gitlab.example.tw/api/v4/packages/npm/
```

:::note
Since you don't need to publish packages here, unlike the Private Package project, you only need to set up the registry proxy. You can also use `npm config set` to configure this.

From testing, unless the publisher is also the user, you'll get a 404 error in both local and CI/CD unless you use a token like in the package project. There are cases where it works, but further testing is needed.
:::

Then, as with any package, use the following command to install:

```shell
npm install --save @group/project
```

GitLab provides two other methods:

- [Example](/blog/2021-07-03)
- [Submodules](https://git-scm.com/book/en/v2/Git-Tools-Submodules)

Alternatively, you can use a self-hosted NPM registry like [Verdaccio](https://www.verdaccio.org/), which is independent of the GitLab workflow.

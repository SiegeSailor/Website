## Communication

Something I learned from the past experiences:

- Infrastructure decisions often involve trade-offs between performance (network), cost, and complexity
- At the end of the day, it is all about finding the right balance that meets the application's requirements and constraints

### CAP Theorem

Partition Tolerance is almost a must nowadays, so the trade-off is usually between Consistency and Availability.

### Trade-Offs

- **Cache**:
  - Pros: Faster access, reduced load on the database
  - Cons: Data inconsistency, cache invalidation complexity
  - Extra: Where to cache is important (client-side, server-side, CDN, etc.). It is really up to the use case. For example, CDN is good for blogs, client-side cache is good for mobile apps. One thing I have noticed that it is becoming important to have cache expiration policies to avoid stale data while keeping an eye from random scraping bots
- **Database**:
  - Pros: Structured data, ACID compliance (for relational databases)
  - Cons: Scalability issues, complex schema migrations
  - Extra: NoSQL databases are becoming more popular for their flexibility and scalability, especially for unstructured data. However, they may sacrifice some ACID properties for performance and scalability (I would argue that since MongoDB 4.0+, multi-document ACID transactions are supported, so it is not a big issue anymore). MongoDB even provides sharding and replication features out-of-the-box. The choice between SQL and NoSQL should be based on the historical data structure and workflows, and the need for sharing versus partitioning. From my experience, always go for NoSQL if the data structure is not well-defined or is expected to change frequently for easier development and scaling
  - Multiple leader pattern actually violates isolation in ACID. More leader, lower consistency
  - In sort, database sharding is like auto-scaling for databases
    - Key (avoid hot spots, no external mapping, problem comes when we need to add nodes, hance need to re-shard all data), range (require a lookup table, easy to organize, no need to re-shard all data, easier to create hot spots), directory (require a lookup table, flexible), and geographic locations
- **API Gateway and ALB and NLB**:
  - Pros: They level down in order, while API Gateway provides features such as request/response transformation, caching, rate limiting, and authentication, NLB only for traffic distribution
  - Cons: The higher the level, the higher the cost
  - Extra: API Gateway can be scaled down to zero
- **Microservices vs Monolith**:
  - Microservices:
    - Pros: Independent deployment, better scalability, fault isolation
    - Cons: Increased complexity, inter-service communication overhead
  - Monolith:
    - Pros: Easier to develop
    - Cons: Can only do vertical scaling

### Two Pointers

This is often used in problems involving arrays or strings, where we need to find pairs or triplets that satisfy certain conditions. The idea is to use two pointers that move towards each other or in the same direction to reduce the time complexity. Sometimes, it can be three pointers.

#### 15. 3 Sum

> See [LeetCode 15. 3Sum](https://leetcode.com/problems/3sum/).

- Sort the given array if possible to create a predictable order
  - Skip duplicates by comparing with the previous/next element when entering a loop
- The outer loop doesn't have to be the left or right pointer, it can be a fixed pointer with the other two moving towards each other

```python {1,4-5,17-20}
nums.sort()
result = []
for i in range(0, len(nums) - 1):
    if i > 0 and nums[i] == nums[i - 1]:
        continue

    target = -nums[i]
    j = i + 1
    k = len(nums) - 1
    while j < k:
        two_sum = nums[j] + nums[k]
        if two_sum == target:
            result.append((nums[i], nums[j], nums[k]))
            j += 1
            k -= 1

            while j < k and nums[j] == nums[j - 1]:
                j += 1
            while j < k and nums[k] == nums[k + 1]:
                k -= 1
        elif two_sum < target:
            j += 1
        else:
            k -= 1

return result
```

### Sliding Window

A window is a subset of contiguous elements in an array that is defined by two pointers. We focus on expanding and contracting the window for the certain value across the window to find the answer.

#### 424. Longest Repeating Character Replacement

> See [LeetCode 424. Longest Repeating Character Replacement](https://leetcode.com/problems/longest-repeating-character-replacement/).

- Think if the most common/rare value can be compared and stored with `max`/`min` to avoid recalculating

```python {8}
result = 0
left = 0
window = Counter()
most = 0
for right in range(0, len(s)):
    window[s[right]] += 1

    most = max(most, window[s[right]])
    while (right - left + 1) - most > k:
        window[s[left]] -= 1
        left += 1

    result = max(result, right - left + 1)

return result
```

### Binary Search

When the given array is sorted or has a certain order, and the problem requires a `O(log n)` solution, binary search is often a good choice.

#### 33. Search in Rotated Sorted Array

> See [LeetCode 33. Search in Rotated Sorted Array](https://leetcode.com/problems/search-in-rotated-sorted-array/).

- Use normal binary search in the correct half, go the other half otherwise

```python {11-14,16-19}
left = 0
right = len(nums) - 1

while left <= right:
    mid = left + (right - left) // 2

    if nums[mid] == target:
        return mid

    if nums[left] <= nums[mid]:
        if nums[left] <= target < nums[mid]:
            right = mid - 1
        else:
            left = mid + 1
    else:
        if nums[right] >= target > nums[mid]:
            left = mid + 1
        else:
            right = mid - 1

return -1
```

#### 34. Find First and Last Position of Element in Sorted Array

> See [LeetCode 34. Find First and Last Position of Element in Sorted Array](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/).

- Can use binary search multiple times to find boundaries
  - When middle equals left or right
  - When there is no more similar element on one side

```python {6-9,22-25}
if len(nums) == 0:
    return [-1, -1]

def findLeftBound(left, right):
    while left <= right:
        mid = left + (right - left) // 2

        if nums[mid] == target:
            if mid == left or nums[mid - 1] != nums[mid]:
                return mid
            else:
                right = mid - 1
        elif nums[mid] > target:
            right = mid - 1
        else:
            left = mid + 1

    return -1

def findRightBound(left, right):
    while left <= right:
        mid = left + (right - left) // 2

        if nums[mid] == target:
            if mid == right or nums[mid + 1] != nums[mid]:
                return mid
            else:
                left = mid + 1
        elif nums[mid] > target:
            right = mid - 1
        else:
            left = mid + 1

    return -1

left = 0
right = len(nums) - 1
mid = left + (right - left) // 2

while left <= right:
    mid = left + (right - left) // 2

    if nums[mid] == target:
        break
    elif nums[mid] > target:
        right = mid - 1
    else:
        left = mid + 1

if nums[mid] != target:
    return [-1, -1]

return findLeftBound(left, mid), findRightBound(mid, right)
```

#### 74. Search a 2D Matrix

> See [LeetCode 74. Search a 2D Matrix](https://leetcode.com/problems/search-a-2d-matrix/).

- Indices can be virtualized by `m * n`, where `m` is the number of rows and `n` is the number of columns
  - Current row is `index // n`
  - Current column in the row is `index % n`

```python {6,8-9}
m = len(matrix)
n = len(matrix[0])
if m == 0:
    return False

left, right = 0, m * n - 1
while left <= right:
    pivot = (left + right) // 2
    pivot_value = matrix[pivot // n][pivot % n]
    if target == pivot_value:
        return True
    elif target < pivot_value:
        right = pivot - 1
    else:
        left = pivot + 1

return False
```

    queue = deque([(row, col)])
    grid[row][col] = "0"

    while queue:
        next_row, next_col = queue.popleft()

        for direction in ((1, 0), (-1, 0), (0, -1), (0, 1)):
            nr = next_row + direction[0]

#### 994. Rotting Oranges

> See [LeetCode 994. Rotting Oranges](https://leetcode.com/problems/rotting-oranges/).

- Set a delimiter like `(-1, -1)` to indicate the end of a round in BFS
  - Append a new delimiter right after encountering one (only when the queue is not empty)

```python {15,20-24}
queue = deque([])
freshes = 0
for row in range(len(grid)):
    for col in range(len(grid[row])):
        if grid[row][col] == 1:
            freshes += 1
        if grid[row][col] == 2:
            queue.append((row, col))

if freshes == 0:
    return 0
if len(queue) == 0:
    return -1

queue.append((-1, -1))
days = -1
rottens = 0
while queue:
    row, col = queue.popleft()
    if row == -1:
        days += 1
        if queue:
            queue.append((-1, -1))
        continue

    for direction in DIRECTIONS:
        next_row = row + direction[0]
        if next_row < 0 or next_row == len(grid):
            continue
        next_col = col + direction[1]
        if next_col < 0 or next_col == len(grid[next_row]):
            continue

        if grid[next_row][next_col] == 0:
            continue
        if grid[next_row][next_col] == 2:
            continue

        queue.append((next_row, next_col))
        grid[next_row][next_col] = 2
        rottens += 1

return days if rottens == freshes else -1
```

### Dynamic Programming

When it comes to finding the maximum/minimum value with previous computations, dynamic programming is often a good choice.

#### 322. Coin Change

> See [LeetCode 322. Coin Change](https://leetcode.com/problems/coin-change/).

##### Top-Down Memoization

- Initialize the DP array with `amount + 1` to make `cache[amount]` more intuitive
- Always cache the minimum value at each step
- The return value can be different from the first time and subsequent times

```python {6-7,15}
def toss(reminder, cache):
    if reminder < 0:
        return -1
    if reminder == 0:
        return 0
    if cache[reminder] != float("inf"):
        return cache[reminder]

    min_cost = float("inf")
    for coin in coins:
        tryout = toss(reminder - coin, cache)
        if tryout != -1:
            min_cost = min(min_cost, tryout + 1)

    cache[reminder] = -1 if min_cost == float("inf") else min_cost
    return cache[reminder]

cache = [float("inf")] * (amount + 1)
return toss(amount, cache)
```

##### Bottom-Up Tabulation

- Increase cost by 1 when needing one or more coins

```python {6-7}
dp = [float("inf")] * (amount + 1)
dp[0] = 0

for current in range(1, amount + 1):
    for coin in coins:
        if current >= coin:
            dp[current] = min(dp[current], dp[current - coin] + 1)

return dp[amount] if dp[amount] != float("inf") else -1
```

#### 198. House Robber

> See [LeetCode 198. House Robber](https://leetcode.com/problems/house-robber/).

- Same as [322. Coin Change](#322-coin-change) but taking care of the initial and jump conditions
- Be careful with the indices and the offset between `nums` and `dp`

```python {2-4,8}
dp = [None] * (last_house + 1)
dp[0] = 0
dp[1] = nums[0]
dp[2] = max(dp[1], nums[1])

for i in range(3, last_house + 1):
    current_money = nums[i - 1]
    dp[i] = max(dp[i - 1], current_money + dp[i - 2])

return dp[last_house]
```

#### 300. Longest Increasing Subsequence

> See [LeetCode 300. Longest Increasing Subsequence](https://leetcode.com/problems/longest-increasing-subsequence/).

- Even with dynamic programming, the time complexity of a valid solution can be `O(n^2)`

```python {7}
dp = [None] * len(nums)

max_count = float("-inf")
for i in range(0, len(nums)):
    current = nums[i]
    dp[i] = 1
    for j in range(0, i):
        previous = nums[j]
        if previous < current:
            dp[i] = max(dp[i], 1 + dp[j])
    max_count = max(max_count, dp[i])

return max_count
```

### Backtracking

Most backtracking problems can be solved with a very similar template, which is defining a recursive function with a base case and a recursive step iterating choices. In the recursive step, we sometimes need to verify if the current choice is valid or not, and we may need to undo the choice after the recursive backtracking call.

#### 46. Permutations

> See [LeetCode 46. Permutations](https://leetcode.com/problems/permutations/).

- Choices' status can be used as an end condition
- Backtrack (`current.append()` then `current.pop()`) is not always needed if we handle `remaining` properly

```python {4}
result = []

def backtrack(current, remaining):
    if not remaining:
        result.append(current)
        return

    for i in range(0, len(remaining)):
        backtrack(current + [remaining[i]], remaining[:i] + remaining[i + 1:])

backtrack([], nums)
return result
```

#### 78. Subsets

> See [LeetCode 78. Subsets](https://leetcode.com/problems/subsets/).

- Can append the current combination at each step without waiting for the end condition
- Keep in mind that `choices` is changing at each step, hence careful using it as a base case condition

```python {4,6-7,9-12}
result = []

def backtrack(current, choices):
    result.append(current[:])

    if len(current) > len(nums):
        return

    for i in range(0, len(choices)):
        current.append(choices[i])
        backtrack(current, choices[i + 1:])
        current.pop()

backtrack([], nums)
return result
```
